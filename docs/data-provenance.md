# Data provenance and public-release policy

This document describes what a public release can contain and how each class
of input should be identified. It intentionally avoids copying raw tables,
partner-provided values, manuscript drafts, or private workstation paths.

The current public seed includes a generated synthetic Lorentz dielectric
table and repository-relative manifests with generation commands and SHA-256
checksums. It does not include a CFO scalar or tensor table. CFO-specific
results described in the research notes come from earlier project runs and
cannot be independently rerun from this repository version.

## Provenance classes

Every public data file should carry a small metadata record with its source
class, units, wavelength or energy convention, transformations, license, and a
checksum. The following classes are used in this project.

| Class | Description | Public-release treatment |
|---|---|---|
| **Code** | Solver, geometry, material readers, checks, and plotting utilities written or legally reusable by the project. | Publish only the maintained copy, with license and dependency versions. Remove caches, compiled files, local environment folders, and machine-specific paths. |
| **Generated geometry** | Parametric particle coordinates, mirror operations, and geometry metadata generated by the project. | Publish when it represents the stated idealized model and contains no restricted sample-identifying information. Include coordinate convention and units. |
| **Public-source material** | Values digitized or transcribed from a paper, open supplement, or openly licensed database. | Prefer a compact derived table plus citation, digitization/rounding metadata, and the source license. Do not mirror a publisher PDF or figure unless redistribution is permitted. |
| **Project-reconstructed material** | A scalar or tensor response obtained by a documented inversion, interpolation, conversion, or finite-window model. | Label as reconstructed or effective. Preserve the full transformation and uncertainty/assumption notes. Do not call it a direct measurement. |
| **Derived result** | Spectra, cross sections, multipole summaries, parity checks, or plots generated by public code. | Publish only with the exact input manifest and evidence label. A derived result inherits restrictions from every input used to make it. |
| **Restricted experiment** | Partner-provided raw CD, UV–vis, absorbance, `g`, or other unpublished measurements. | Do not publish values, files, or value-revealing derived outputs until explicit redistribution permission is recorded. |
| **Manuscript material** | Draft papers, marked-up files, reviewer comments, collaboration documents, and document-build intermediates. | Keep outside the public repository unless all authors explicitly release the exact version. Summarize scientific conclusions separately. |

## Material-input records

### Scalar CFO input

The project has used more than one scalar CFO input at different stages. Early
baseline work used a finite-window scalar reconstruction from optical data and
recorded its preprocessing, tail handling, and effective-medium assumptions.
Later publication-oriented comparisons used a corrected, digitized literature
dispersion with ascending-energy interpolation. These are distinct provenance
records and must not be silently combined.

For a public copy, record:

* whether the data are reconstructed from optical measurements or digitized
  from a published curve;
* the wavelength/energy ordering and interpolation direction;
* baseline subtraction, clipping, extrapolation, and unit conversions;
* whether the table is scalar and isotropic;
* the validation checks that were run and the spectral window they cover.

The public description must say that a finite-window or reconstructed scalar
function is an effective model input, not an independently certified bulk or
nanoparticle optical constant.

### Magnetization-dependent tensor input

The tensor branch uses paired `+M` and `-M` dielectric-response tables with a
declared magnetization axis and frequency convention. The public release may
include the compact tensor table and the parity checker only if the table is
redistributable. The checker should report diagonal evenness, off-diagonal
oddness, units, coverage, and the residual tolerance.

The accompanying provenance must state that the tensor is an idealized bulk
input for a reduced calculation. The project does not package the original
electronic-structure files, per-atom magnetic moments, or magnetization-density
fields needed to reproduce the electronic-structure calculation from scratch.
The tensor CDM output is consequently a diagnostic, not a nanoparticle
measurement.

### Organic PS-b-PAA input

The later organic branch constructs an effective optical input from literature
constituent `n,k` data. The documented operations are:

1. identify the source and sample state for each constituent curve;
2. digitize or evaluate the stated source representation;
3. apply the project’s equal-weight complex-index mixing rule;
4. convert the mixed complex index to the complex dielectric function;
5. record extrapolated regions, missing source vectors, and sensitivity inputs.

This is a literature-constrained effective model, not a direct measurement of
the specific block-copolymer sample. It does not encode an explicit CFO core,
polymer shell, block morphology, density conversion, or interfacial geometry.
Finite-band consistency checks of selected source curves should be labeled as
diagnostics rather than a full Kramers–Kronig proof.

## Experimental and collaboration data

The project history contains partner-provided experimental spectra and tables
used as targets in conditional CD analyses. This public repository does not
include those raw files, their numerical values, collaboration drafts, marked
documents, or figures that expose the same restricted values unless the data
owners grant written redistribution permission.

If permission is later granted, add a provenance entry that identifies:

* the data owner and the permitted license or scope;
* whether raw values, processed values, and derived outputs are covered;
* the sample state, units, calibration, and preprocessing;
* the exact release/version and checksum;
* any citation or embargo requirement.

Without that permission, the public repository may contain code that accepts a
user-supplied table, a schema/example with synthetic values, and a description
of the required columns. It must not contain a disguised copy of the partner
table or a result that allows the restricted values to be reconstructed.

## Derived-result policy

A result is public only when all of the following are true:

1. every input is public or explicitly licensed for redistribution;
2. the calculation script and convention record are present;
3. the result has a machine-readable manifest and checksum;
4. the evidence label and limitations are written next to the result;
5. the result does not disclose a restricted measurement or manuscript.

This rule applies to CSV files, plots, fitted coefficients, scale factors,
geometry snapshots, packaged archives, and notebook outputs. A value generated
from restricted data remains restricted even if the arithmetic was performed by
public code.

## Recommended public manifest fields

Each released input or result should record, in a small JSON or CSV manifest:

```text
file
role
source_class
source_citation
license_or_permission
sample_or_model_state
units
axis_and_ordering
transformations
extrapolation_or_missing_regions
code_version
validation_status
sha256
```

Paths in these manifests must be repository-relative. Do not include usernames,
desktop locations, private drive letters, temporary build directories, or chat
transcripts.

## Reproducibility tiers for this repository

**Tier A — fully public rerun.** Public code, public inputs, a clean environment
specification, and validation output are all present. The scalar Mie benchmark
and small synthetic CDM examples should target this tier.

**Tier B — public method, conditional data.** The code and method are public,
but an input is an effective reconstruction, a supplied tensor, or a declared
model convention. The output is reproducible only under that condition and must
be labeled accordingly.

**Tier C — restricted target.** A calculation uses partner-provided or
unpublished experimental data. Keep the data and value-revealing outputs out of
the public release; publish only the method interface or a synthetic example.

The PS-b-PAA experimental CD attribution belongs to Tier C until the target
data and all derived outputs have explicit release permission. Public-source
material construction can be documented separately at Tier B, without claiming
that the restricted experiment has been reproduced.

## Versioning and corrections

When a material interpolation, normalization, or scale convention is corrected,
keep the old result only in a clearly marked private or historical archive. The
current public release should regenerate figures from the corrected input
chain and state the change in a short changelog. In particular, theoretical
mirror-branch normalization must be kept separate from an empirical experimental
branch rescaling.

Publication-panel CSV exports and geometry snapshots generated from model
coordinates are derived presentation artifacts. Their provenance should point
back to the corrected input chain and the rendering script; they should not be
registered as new measurements or as an independent morphology reconstruction.
